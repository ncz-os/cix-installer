## Section D — Silent-Stall Theories

1. Hypothesis 1, highest rank: d-i is running only on the preferred serial console, leaving tty1 with a cursor, and it is waiting before netcfg. Source path: preseed/simple mode restricts d-i to one console (`.kernel-source-readonly/di-initrd/sbin/reopen-console:46`, `.kernel-source-readonly/di-initrd/sbin/reopen-console:47`, `.kernel-source-readonly/di-initrd/sbin/reopen-console:53`, `.kernel-source-readonly/di-initrd/sbin/reopen-console:54`, `.kernel-source-readonly/di-initrd/sbin/reopen-console:55`, `.kernel-source-readonly/di-initrd/sbin/reopen-console:56`, `.kernel-source-readonly/di-initrd/sbin/reopen-console:110`, `.kernel-source-readonly/di-initrd/sbin/reopen-console:112`), only that console gets `respawn:/sbin/debian-installer` (`.kernel-source-readonly/di-initrd/sbin/reopen-console:122`, `.kernel-source-readonly/di-initrd/sbin/reopen-console:126`), and serial consoles run through the screen/menu path (`.kernel-source-readonly/di-initrd/lib/debian-installer.d/S70menu:13`, `.kernel-source-readonly/di-initrd/lib/debian-installer.d/S70menu:24`, `.kernel-source-readonly/di-initrd/lib/debian-installer/menu:19`). 2. Hypothesis 2: main-menu is blocked before netcfg while detecting/loading installer components from the ISO, so no DHCP is attempted.
