## What's NEW vs prior handoffs

Compared to `HANDOFF-2026-05-03-AUTOPILOT.md`:

1. **Casper userspace abandoned.** r17-r24 fought casper; root cause was missing `boot=casper` cmdline flag (kernel boots fine, casper init never runs without it). After fixing that, casper still proved unreliable on Sky1. Pivoted to bookworm d-i — proven stable.

2. **bookworm-d-i + trixie-userspace graft architected.** Bookworm's busybox `/init` boots Sky1 cleanly; trixie's debootstrap (1.0.141 shell, replaces bookworm's cdebootstrap-static binary) handles zstd-compressed Ubuntu questing debs natively. The graft swaps 5 specific udebs (debootstrap, libzstd1, liblzma5, base-installer 1.226, bootstrap-base 1.226) into bookworm's pool, regenerates the d-i Packages.gz via `dpkg-scanpackages`, regenerates dists/questing/Release. Validated by GRAEAE multi-muse architectural review and 3 Codex adversarial code reviews.

3. **Offline mirror baked in.** 2.2 GB / 2573 questing arm64 debs in `/cdrom/pool/main/`. Built by `build-mirror.sh` via `debootstrap minbase questing` chroot + `apt-get install -d --reinstall <full-pkg-list> + everything-installed`. Generated via `apt-ftparchive` matching real Debian DVD-1 structure (per-component Release files, Translation-en stub, single Components: main entry, hash chain validated).

4. **Sky1 firmware path fix landed.** `12-sky1-firmware.sh` now creates `/lib/firmware/mali_csffw.bin → arm/mali/mali_csffw.bin` symlink, fixing the panthor `[drm] *ERROR* Failed to load firmware image 'mali_csffw.bin'` we observed on the running r6 install.

5. **DVD-correct ISO structure.** xorriso flags now match bookworm DVD-1 exactly: `-e boot/grub/efi.img -no-emul-boot -append_partition 2 0xef <efi.img> -appended_part_as_gpt -partition_cyl_align all`. ESP appears at GPT slot 2 type 0xef, observed via `lsblk` after dd.

6. **Disk wipe early_command.** preseed `partman/early_command` runs `wipefs -a + sgdisk --zap-all + dd if=/dev/zero count=10` on /dev/nvme0n1 before partman starts, fixing the red "filesystem already exists" warnings on disks with prior r6 installs.

7. **Bootloader failure now fatal.** `post-install/run-all.sh` was masking 70-bootloader.sh failures; now propagates exit code so late_command fails loudly instead of "successfully" finishing without a bootloader.

8. **Offline apt during late_command.** late.sh bind-mounts `/cdrom → /target/cdrom` and adds `deb [trusted=yes] file:///cdrom questing main` to `/target/etc/apt/sources.list.d/cixmini-cdrom.list`. All `apt-get install` calls in post-install hooks now work offline.

## Hardware/platform findings (worth documenting in PR/blog)

1. **Sky1 USB UEFI is finicky about init script complexity.** Bookworm d-i busybox `/init` works; casper systemd-in-initrd-style hits failures (likely DRM master grab race or systemd watchdog timeout).
2. **Linlondp DRM has 5 cards (CIXH5000_00..04, the 5 DPU pipes).** Default udev tags ALL as `master-of-seat`. Mutter picks card0 (which has no connected output on MS-R1 — DP-4 is on card3). Fix: `73-cixmini-primary-display.rules` strips master-of-seat from cards 0/1/2/4. Filename priority must be > 71 (after systemd's 71-seat.rules).
3. **panthor (Mali-G720 GPU driver) requests `mali_csffw.bin`** with no path prefix. Sky1-firmware ships it at `arm/mali/mali_csffw.bin`. Fix: symlink in `/lib/firmware/`.
4. **MS-R1 BIOS 1.0 has not been updated since launch** (~6 months as of 2026-05-04). Cixtech's commits `ad5281ee` (UEFI backward-compat patches) + `c3e05f4d` (PWM driver) compensate for older BIOS quirks. We have the patches in 6.18.26-cix-sky1-lts.
5. **Kernel mali_csffw firmware loading is non-fatal.** Without firmware, panthor probe fails with `-2` (-ENOENT), but linlondp KMS still works for display via efifb fallback.
6. **GPT vs MBR on Sky1 UEFI.** ESP must be a real GPT entry (type 0xef). xorriso `-isohybrid-gpt-basdat` is INSUFFICIENT — must use `-append_partition 2 0xef <efi.img> -appended_part_as_gpt`.
7. **Bookworm d-i lacks zstd entirely.** No userspace libzstd library, no `zstdcat` binary, cdebootstrap-static C binary has no zstd hooks compiled in. Modern Ubuntu .debs (data.tar.zst) are unextractable.
8. **Trixie d-i replaced cdebootstrap with debootstrap.** debootstrap-udeb 1.0.141 (architecture: all, shell scripts) handles zstd by shelling to zstd binary. This is the major Debian-Installer architecture change between 12 and 13.
