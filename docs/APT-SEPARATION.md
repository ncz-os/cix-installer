# Separating NCZ-OS package updates from Debian ones

Operator request, 2026-10-07: "certain system updates for apt were flagged, we
need to make sure our ncz-specific updates are separated from the debian ones."
Branch `fix/r201-apt-separation-20261007`, off the respin `d287f207`.

## What was wrong (measured on r200 images, MEDUSA amd64 and O6N arm64)

| Finding | Evidence |
|---|---|
| A Debian-named package from the NCZ repo shadows Debian's. | `fonts-liberation 1:2.1.5-3build1` (Ubuntu build, `Maintainer: Ubuntu Developers`) is in the Buildkite repo. It sorts above Debian's `1:2.1.5-3`, so apt offers it as an update on amd64, and arm64 images had already *installed* it. |
| Two NCZ repos are enabled and overlap. | `ncz-os-apt-buildkite.list` (19 packages) and `ncz-os-apt-r2.list` (13). The four `ncz-wallpapers-*` 1.0 exist in both with different content; apt shows `1.0 -> 1.0`. |
| Same-version rebuilds. | apt keys a version by (version string, package metadata hash). A rebuilt 1.0 is a different version that prints the same. |
| No pin separates NCZ from Debian or from the third-party T2 repo. | Only `00-ncz-kernel-purity.pref` exists. |
| The NCZ repo cannot be recognised by `Origin`. | Buildkite Packages is a managed registry: its Release says `Origin: packagecloud.io/<uuid>`, `Label: <uuid>`. Only the reprepro/R2 copy says `Origin: NCZ-OS`. The T2 repo has no Origin at all. |
| The Singularity Store does not see apt at all. | `singularity-store-updates` runs `flatpak --user remote-ls --updates` and nothing else. The component that lists apt updates is the NCZ-owned `ncz-update-check` (this repo). |

## Design

1. **Origin by host, not by Origin field.** `Pin: origin <host>` matches
   `packages.buildkite.com` and the R2 host. No dependency on a field we cannot
   set, and deliberately no `release o=NCZ-OS` stanza: the offline install
   mirror (`build/build-forky-mirror.sh`) is stamped `Origin: NCZ-OS` and its
   Debian-named packages must keep apt's default priority (tested in
   `build/test-apt-separation.sh` scenario B).
2. **Priority tiers** (`/etc/apt/preferences.d/10-ncz-origin-separation.pref`,
   generated by `post-install/lib/apt-separation.sh`):

   | Source | Package | Priority |
   |---|---|---|
   | NCZ | `ncz-* cix-* cixmini-* chromium-ncz-* panthor-cix-dkms zoder linux-image-* linux-headers-*` | 990 |
   | NCZ | allowlisted Debian-name overrides (`libdrm*`) | 990 |
   | NCZ | anything else, i.e. a Debian-named package | 100 (Debian's 500 wins) |
   | Debian | `ncz-* cix-* cixmini-* chromium-ncz-*` | -1 (Debian cannot hijack) |
   | any | leaked `fonts-liberation 1:2.1.5-3build1` | -1 |
   | Debian | `intel-opencl-icd libze1 libze-intel-gpu1` | 990 (Debian's runtime beats any Ubuntu build Intel's repo carries) |

   990 and not 1000+, so nothing ever forces a downgrade. The former third-party
   T2 stanzas are gone (r201 native-vendor closure, 2026-10-08): `55-t2-firmware.sh`
   wires no third-party T2 apt source, so there is no T2 host to pin. Verified
   2026-10-08 against the pinned forky snapshot: Debian ships **no** openvino
   package, so the Intel plugin needs no pin.
3. **One NCZ repo.** Buildkite is enabled: it is the superset (zoder, libdrm,
   `ncz-model-nomic-embed` that R2's 300 MB single-PUT rejects) and the
   2026-07-26 operator primary. R2 stays staged as
   `ncz-os-apt-r2.list.disabled` with its keyring; `ncz-apt-source r2` swaps
   them (never both). If the Buildkite keyring cannot be staged at install,
   R2 is enabled instead so the install still works. The offline `/cdrom` pool
   is untouched.
4. **Labelled updates.** `ncz-update-check` classifies each candidate by apt
   origin into `ncz-os`, `debian` or `third-party`; the Update Manager shows
   three sections and the notifier says "3 NCZ-OS + 5 Debian updates available".
   A same-version rebuild is marked "[rebuilt, same version]".
   `/etc/ncz-os/update-origins.conf` (`ncz-os <host>`) adds hosts without a code
   change. Nothing in upstream Singularity changes. Upstream candidate: a
   generic "apt origin/label" grouping in the Store, which today is Flatpak-only.
5. **Delivery of the pin.** New installs: hook 24 writes it before any other
   apt operation. Everyone, including already-installed r200 machines: the
   `ncz-apt-policy` package (1.0.2; `build/build-ncz-apt-policy-deb.sh`) rewrites
   the pin in its (bash) postinst and migrates a dual-repo configuration. A
   standalone package does not install itself, so it is delivered by
   `manifests/install-extra.pkgs` (+ SBOM rows, `components.tsv`; images), hook 24
   (best effort at install), and `ncz-update-apply`, which installs it after every
   index refresh and before the upgrade is planned (installed systems). There is
   deliberately NO Depends from `ncz-singularity-desktop`: the payload debs are
   built against exact versions and ABI-gated, and a new Depends would force a
   rewrap and make the deb uninstallable until the policy package is published.
   `build/verify-installed-target.sh` requires it installed in every image. 1.0.0 had a `#!/bin/sh` postinst that died under
   dash and must never be published.
6. **Single-repo outage behaviour.** Only Buildkite is enabled, so a Buildkite
   outage during `apt update` is a warning and the installed system keeps
   working from what it has; `ncz-apt-source r2` switches to the (smaller) R2
   copy until Buildkite returns. At install time the offline `/cdrom` pool is
   still wired, so an offline install is unaffected; the live-update canary in
   hook 24 warns (not fails) when only the pool resolves.
7. **Role images.** The pin and the single enabled repo are written by hook 24
   on the target, which runs for every variant (desktop and server alike; it is
   in both `hooks.list.*`). The mkosi role-delta no-mirror fallback writes the
   pin into its build tree only for the build. `build-mgmt-rootfs.sh` and
   `build-rescue-rootfs.sh` do not configure NCZ repos at all, so they have
   nothing to separate.

## Gates (each tested in both directions)

| Gate | Fails when |
|---|---|
| `build/check-ncz-repo-policy.sh INDEX...` / `--components` / `--live` | a Debian-named package is published or seeded in the NCZ suite and is not an allowlist row for that architecture, or is a Debian kernel name |
| `ncz-reprepro-publish.sh` policy block | same check, before `includedeb`, fail closed; also refuses a same-version republish with different bytes |
| `build/check-installed-apt-config.sh [ROOT]` | pin file missing or stale, kernel-purity pin missing, two NCZ repos enabled; a stale `t2.list` is noted |
| `build/lib/deb-version-gate.sh` in the wallpaper, usb-recovery, dkms, singularity, libdrm and policy builders | a package reuses a published version with different content |
| `build/verify-installed-target.sh` (section `apt`) | an installed image fails the audit above or lacks `ncz-apt-policy` |
| `build/preflight-sbom-check.sh` | `check-ncz-repo-policy.sh --components` fails (always fatal); the live index check only WARNS here (`build/apt-live-gate.sh warn`) |
| `build/ship-image.sh` | `build/apt-live-gate.sh fail`: a Debian-named package published in the live NCZ repos blocks shipping (read-only; skips when the indexes are unreachable) |
| `build/test-install-extra-local-debs.sh` | an `ncz-*` seed in `install-extra.pkgs` that the offline-mirror build cannot resolve (no `NCZ_LOCAL_DEBS` row / no builder), for both arches |
| `build/test-ncz-apt-policy-deb.sh` | the built deb's scripts do not parse under their own interpreter, or the real `dpkg -i`/reinstall/purge in debian:forky is not clean (negative control: the 1.0.0 sh postinst) |
| `build/test-apt-separation.sh` | real apt resolution against throwaway Debian / NCZ(http) repos: old behaviour reproduced, new behaviour asserted |
| `build/test-ncz-repo-policy.sh` | the gates above, plus update classification of MEDUSA's recorded r200 output |

The writer only ever removes the four exact `ncz-os-apt-{buildkite,r2}.list[.disabled]` names; it never touches a foreign vendor list.

## Version identity

File modes are part of the identity and come from the builder's umask, so every builder that makes
a published or staged deb sets `umask 022` (`build/test-ncz-repo-policy.sh` section 7 lists and proves it).
`ncz_policy_deb_lib_check` inside `build-ncz-apt-policy-deb.sh` compares the deb with the library it was
just built from, so it cannot fail: it is a build sanity check, not protection. The protection is the
publisher call against the library deployed in `~/ncz-policy`; a deployed gate library that predates the
function makes the publisher fail closed (command not found), so redeploy both libraries (step 0).

The gate compares a normalised content identity (control fields, maintainer
scripts, the `dpkg-deb -c` listing without mtimes, and the sha256 of every data
file), not the bytes of the .deb: our builders are not all reproducible. An
unchanged rebuild of a published version is allowed; a changed file, mode or
control field at the same version is refused with the first differences.
`ncz-usb-recovery` is bumped to 1.2 because the published 1.1 (Architecture: all)
is a genuinely different package from what the repo builds (Architecture: arm64).

## Version discipline

A rebuilt package must bump its version. The wallpaper default moved to 1.1 and
its bytes are now reproducible (`SOURCE_DATE_EPOCH` from the last commit that
touched the packaging script or art), so re-running a build is idempotent and
changing content without bumping is refused.

## Operator runbook: live repo actions (NOT done by the branch)

Run on ARGOS (reprepro in `~/ncz-apt-repo`, codename `any`), then publish
through `build/ops/argos/ncz-reprepro-publish.sh`, which dual-publishes.

0. Deploy the gate libraries next to the publisher:
   `mkdir -p ~/ncz-policy && cp post-install/lib/apt-separation.sh build/lib/deb-version-gate.sh ~/ncz-policy/`
   and replace `~/bin/ncz-reprepro-publish.sh` with the branch version.
1. Remove the leaked package from the NCZ suite:
   `reprepro -b ~/ncz-apt-repo remove any fonts-liberation`, then delete
   `fonts-liberation_2.1.5-3build1_all.deb` from the Buildkite registry
   (Buildkite API or UI, org `ncz-os`, registry `ncz`) and from the R2 bucket
   `ncz-apt` (pool object + republish `dists/any/*`).
2. Bump and republish the four wallpaper packs
   (`build/build-wallpaper-contrib-deb.sh {ncz,singularity,alex-jay-brady,brandon-perlow}`
   builds 1.1) and publish them.
3. Build and publish `ncz-apt-policy` 1.0.2 from the **exact final head**
   (`build/build-ncz-apt-policy-deb.sh`): the library changed (r201 native-vendor
   closure — the unreferenced T2 pending-host pin stanzas are gone and the Intel
   runtime is pinned `release o=Debian`), so the version moves to 1.0.2; any
   earlier-tip 1.0.2 must be discarded.
   The publisher refuses a deb whose packaged `apt-separation.sh` differs from
   the copy deployed in `~/ncz-policy` (step 0), and the version gate refuses a
   later same-version rebuild with different content. Publishing is needed only
   for installed systems (hook 24 and `ncz-update-apply` install it from the live
   repo). **An image build needs no publish**: the offline mirror gets the
   package as a LOCAL deb (`make apt-policy-deb` -> `build/ncz-apt-policy-deb`,
   the `NCZ_LOCAL_DEBS` row in `build/build-desktop-mirror.sh`), for both
   architectures (it is `Architecture: all`).
   The live-repo gate: `build/preflight-sbom-check.sh` only WARNS while the
   leaked `fonts-liberation` is still published (step 2; `NCZ_APT_LIVE_GATE=fail|warn|skip`
   applies there). `build/ship-image.sh` runs `build/ship-apt-gate.sh`: always fail mode,
   it IGNORES `NCZ_APT_LIVE_GATE`, treats an unreachable or empty index as a failure, and can
   be weakened only with `NCZ_SHIP_ALLOW_APT_GATE_OVERRIDE=1` plus `NCZ_APT_LIVE_GATE=warn|skip`
   (logged loudly).
   An existing `build/desktop-mirror` is reused only if `verify-desktop-mirror-seeds.sh` passes,
   and that verifier now also requires every `NCZ_LOCAL_DEBS` package at its current local
   version, and the ncz-apt-policy deb with the same content (pin) as the one just built; a mirror
   built before the row existed, or from an older pin, is rebuilt.
4. Confirm the R2 Release keeps `Origin: NCZ-OS` (`conf/distributions` on ARGOS)
   and that `build/check-ncz-repo-policy.sh --live` ends clean.
5. Optional: backfill R2 so the fallback is not degraded (it lacks zoder,
   `libdrm2`/`libdrm-common`, and the `ncz-model-nomic-embed` pool object, which
   R2's single-PUT limit rejected with HTTP 413).

## Known limits

* A machine that already installed the leaked `fonts-liberation` keeps it (the
  leaked version is pinned -1 so it is never offered, and apt does not
  downgrade by itself). `apt install fonts-liberation=1:2.1.5-3` cleans it up.
* The wallpapers still show `1.0 -> 1.0` on installed machines until 1.1 is
  published; the single repo removes the flip-flop but not the stale 1.0.
* Libdrm packages other than `libdrm2` and `libdrm-common` are allowlisted for
  the offline pool but are not published; when they are, the pin already
  covers them.
