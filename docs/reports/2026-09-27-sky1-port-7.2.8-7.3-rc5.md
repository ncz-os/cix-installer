# Sky1 mechanical port impact: v7.2.8 and v7.3-rc5

Date: 2026-09-27

Scope: measurement only. No kernel was built, packaged, flashed, or booted.

## Method and provenance

`build/port-series.sh` was run from the fresh `cix-installer` clone without modifying the tool. The tool used its intended default live recipe directory, `/home/jasonperlow/yocto-work/meta-cix/recipes-kernel/linux-cix-sky1-ncz`, so it replayed the 205 patches actually wired by that recipe in `SRC_URI` order. The recipe SHA-256 was `5e770d5c0428fa8ec1c6931dd825833212931e6fc69935029add7c46f2406598`; its patch directory was clean at meta-cix commit `6e02f69921cc1c5e645a719674809d9489b2705d`. The recipe itself had an existing local version/SRCREV edit and identified the stable pin as v7.2.7 (`f42acb367842...`), not v7.2.6. The wired patch set was nevertheless the current 205-patch Sky1 series requested for measurement.

The installer repository's mirrored recipe was not used: it is stale at v7.2 with only 202 wired patches. Using it would not measure the series the build tool selects by default.

Kernel remote verification:

- `stable` is `https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux-stable.git`.
- `origin` is `https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git`.
- v7.2.8 was present from the stable remote. Annotated tag object `c4589b1a32fcdcc949d038fb662bf41b15403e68` peels to replay commit `9a66fdc0d7fd55f54235524a73435af99051e46f`.
- v7.3-rc5 was fetched from Torvalds' remote, not stable. Annotated tag object `5a956dde5526a634dca7ccad27c051ebcc306089` peels to replay commit `72d3fcf802c45d00b300f25b848a93c3a2bd7c7e`.
- The existing edge worktree is based on v7.3-rc4 (`93f51579e7df...`), not rc3. A control replay on rc4 produced 178 applied / 27 failed / 205, with exactly the same failure list as rc5.

Raw tool output is in `sky1-port-v7.2.8.raw.txt` and `sky1-port-v7.3-rc5.raw.txt` beside this report.

## v7.2.8 result

**205 applied / 0 failed / 205 wired.**

Failure list: none.

Overall read: routine mechanical stable update. The entire currently wired Sky1 series still applies. This is an application measurement only, not evidence that the kernel builds or runs.

## v7.3-rc5 result

**178 applied / 27 failed / 205 wired.**

The rc4 control has the same 178/27 result and identical failures. Of all files touched by the 27 failed patches, rc4..rc5 changes only `drivers/base/cacheinfo.c` (commit `3cb0243767fd`, scheduler capacity refresh), and patch 0212 already failed on rc4. Therefore rc5 introduces **zero new Sky1 replay failures**. The list below classifies the raw failures themselves.

Classification key: (a) upstream took the intent; (b) intent still needs a forward-port because code/context moved (including follow-ons whose prerequisite failed); (c) upstream behavior or a replacement implementation materially interacts with the patch, so it needs an explicit human decision rather than a mechanical resolution.

Totals by class: **(a) 4, (b) 19, (c) 4**. Class (c) patches are 0027, 0029, 0058, and 0074.

Overall read: the rc4→rc5 increment itself is routine—there are no new failures and no rc5-specific behavioral collision. The edge series still carries pre-existing raw-replay debt from the already-known v7.3 transition. The four class-(c) items should remain explicit human decisions; they must not be force-applied. The other non-obsolete failures are forward-port/dependency work already present at rc4, not regressions caused by rc5.

## Required follow-on before shipment

Neither line can ship merely on this measurement. A new kernel version requires rebuilding **every** accelerator DKMS overlay against the new headers: **mali/panthor, VPU (`cix-vpu-driver`), GPU-KMD (`cix-gpu-kmd`), and NPU (`cix-npu-driver`)**. This is a closed set with no exceptions. Those rebuilds were deliberately not performed here.
