## Kernel changes

1. **`ac358595495b` 0058 drop and linlon-dp re-aim.** Unchanged since the
   advisory branch.
2. **`4cf94b2fd097` + `02e001301435` native Sky1 PCIe.** The 0027 remainder
   plus 0029. The rc5 port had three native-mode defects:
   - The driver-name clash. Measured in the KVM gate: r278 logs `Error:
     Driver 'sky1-pcie' is already registered, aborting...` at 0.089528s.
     r279 does not.
   - The LGA root-port base `0x200000` was used on an HPA controller, and an
     `__iomem` window was passed as `struct cdns_pcie *` into
     `cdns_pcie_find_capability()`.
   - The HPA ECAM outbound region was never programmed.

   All three are fixed, along with the ACPI vendor-id/device-id/
   no-inbound-bar properties and 0029's CLKT-keyed clocks. The mainline
   pci-sky1.c path is unchanged: the ECAM programming is gated on a new flag
   that only the vendor driver sets.

   The zoder review fixes in `02e001301435` cover three more items:
   - A clock lookup failure used to leave an `ERR_PTR` that
     `clk_prepare_enable` would dereference. It now defers.
   - AER root-command re-enable wrote the PCIe capability instead of the AER
     capability. This bug was also in r277.
   - The synthetic pdev is renamed `sky1-pcie-cix`.

   History: on 2026-09-16 the rc3 edge entry, which lacked
   `sky1_pcie_native=off`, hard-reset O6N at USB bring-up. That is
   consistent with these defects but not proven. Native mode stays off on
   every shipped cmdline. Boot sheet section N gates it.
3. **`24dc015b0c01` 0089 runtime-PM gate.** Ported verbatim from r277 onto
   v7.3 runtime.c. The KVM boot logs `cix_pm: system ready - pm_runtime
   callbacks enabled`.
4. **Config.** `CONFIG_MODULE_COMPRESS` is off, so modules are plain `.ko`.
   This follows the fleet rule; r277 and r278 shipped `.ko.xz`. Every
   consumer in this repo already handles both forms. The d-i initrd
   decompression step in `build-iso-di.sh` becomes a no-op for Sky1.

## Status of the rest of the patch list, verified against source

- **CLKT chain 0096/0138/0147/0148/0157/0168.** `drivers/clk/cix` is
  identical to r277 except for `clk-sky1-audss.c`, so the chain is at parity.
  The per-patch added-line check agrees: the lines missing in the port are
  also missing in r277, because later patches superseded them.
- **0172.** This corrects the advisory report, which said
  "`cix_scmi_register_em()` has no caller". Its caller is out of tree:
  `mali_kbase_devfreq.c:772` in the mali DKMS source. The r279
  `mali_kbase.ko` imports it, and vmlinux exports it. Removing the export
  makes the overlay check report it unresolved (negative control). Boot
  sheet D21 checks the GPU energy model on metal.
- **0091.** Already carried (`6d3cab5b0154`, `9291c638f97a`).
  **0001.** Already carried.
- **0212 (cacheinfo PPTT global IDs).** Not ported. No 7.3 symptom has been
  observed. Boot sheet D22 compares cache topology with 7.2.8, and a
  difference re-opens it.
- **0216 (resctrl MB_PROP).** Not ported: it is inert because
  `CONFIG_ARM64_MPAM` is off.

## Accelerator overlays (all four DKMS drivers)

`build/build-accel-overlays.sh` is new. It runs each driver's own
`dkms.conf` `MAKE[0]` over the same `src/` tree that `build-dkms-debs.sh`
packages, then checks every module:

- vermagic matches the KVER;
- the GNU build-id is present;
- the module is uncompressed ELF;
- 0 undefined symbols are unresolved against `Module.symvers` or a sibling
  overlay.
