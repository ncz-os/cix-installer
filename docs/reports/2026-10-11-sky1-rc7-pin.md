## NEED-OPERATOR.md

This pin is **NOT** installable as-is. The accelerator overlays from r287
are built against `7.3.0-rc6-sky1-ncz` and will refuse to load against
`7.3.0-rc7-sky1-ncz` (moved CRCs). Before any image can ship r288:

1. Rebuild the six accelerator DKMS debs (mali/panthor/vpu/npu) against the
   r288 headers (`build/build-accel-overlays.sh mali panthor vpu npu` per
   the r287 release runbook; same shape as r282->r284 and r285->r287).
2. Re-mirror the `.ko` files into `assets/kernel/{mali,npu,panthor,vpu}/7.3.0-rc7-sky1-ncz/`.
3. Run `verify-overlay-modversions.py` -> 0 mismatches.
4. Optionally apply the r287 audio-cutout fix (`CONFIG_RT_GROUP_SCHED=n`) and
   the CIX q3 sync patches 0013-0021 to produce r289 (the proper post-rc7
   audio-clean build). r288 as-shipped inherits the rc6 RT_GROUP_SCHED=y.

## Boot validation (operator-present)

**Required** on .66 (MS-R1) and O6N before this kernel is trusted:

1. Boot the default entry on .66 (MS-R1, real 4K panel, the AUX-wedge
   repro board). Measure:
   - `journalctl -b 0 -k | grep "failed to do aux transfer"` count (expected: 0 on clean boot; if non-zero, the v2 fix is not protecting this path)
   - `grep -c "AUX engine wedged" /var/log/kern.log` (new v2 warning; expected 0 on .66 normal boot)
   - Time to first visible frame (photo): the v2 fix targets a < 100 ms recovery from a wedged AUX engine, vs the operator-reported ~75 s on .66 pre-fix
2. Boot the default entry on O6N (the DP->HDMI dongle). Regression
   checklist: `grep -c "failed to do aux transfer" = 0`,
   `grep -c "AUX engine wedged" = 0`. O6N never returns -EBUSY so the new
   code paths are unreachable; topology/greeter/GPU unchanged.
3. With the r288 default on .66, the `trilin_dp_aux_recover_max=2` module
   parameter (default 2) bounds the recovery attempts. If the AUX engine
   wedges persistently, `modinfo trilin_dpsub` shows the parameter;
   `echo N > /sys/module/trilin_dpsub/parameters/aux_recover_max` raises
   the bound. KVM is not a substitute for the metal test.
4. The O6N audio cutout is expected to persist on r288 (RT fix NOT
   applied). This is a known carry-over to r289.

## Risks

- **r288 inherits the rc6 audio-cutout bug.** The O6N audio will cut
  out under load as on r286. The fix is in r289 (r287's CONFIG_RT_GROUP_SCHED=n).
  r288 is a SHAPE-PRESERVING port to validate the rc7 rebase works, not
  a sound fix.
- **Overlays not rebuilt.** r288 cannot be installed on a board today; it
  will Oops in panthor/mali/amvx as soon as the first userland hits the
  GPU. Operator is the gate for the image-build follow-up.
- **cix-installer build-kernel-debs.sh not run.** The cix-installer-style
  `linux-image-cixmini_7.3.0-rc7-sky1-ncz+r288_arm64.deb` and the matching
  `cixmini-boot_1.2+r288_arm64.deb` are NOT produced. The Yocto
  bitbake output (`kernel-linux-cix-sky1-ncz-image-7.3.0-rc7-sky1-ncz_7.3-rc7+ncz0+ec8bf82802-r1_arm64.deb`)
  is in the staging dir as `debs/linux-image-cixmini_*.deb` (renamed by
  the kport stage script for the build process); cix-installer is
  expected to run its own `build/build-kernel-debs.sh x2` on a future
  image-build to byte-replace the cix-installer-style debs and update
  the ncz-packages.tsv sha256s. The current pin's `<pending>` markers
  are honest.
- **No zoder review** (per operator brief: zoder review required for
  cix-installer pin; this kernel pin is a non-code change, just pin
  metadata). The actual code change is the r288 port branch in linux-cix
  which inherits the 207-commit rc6 series (each commit was reviewed at
  its original landing; the rebase is mechanical, zero conflicts, no
  content change) plus the dptx-aux-wedge-recovery-v2 (already 6 rounds
  zoder reviewed in the dpfix session).
- **No new patches beyond rc6 + v2 DP fix.** Anything rc6 carries forward
  as-is. Notable carry-overs:
  - CONFIG_RT_GROUP_SCHED=y (O6N audio cutout; see r287)
  - 0004/0005/0065/0105: not re-applied (CIX 7.2 series form)
  - 0027/0029: CIX Cadence PCIe native mode is partial (cmdline
    `sky1_pcie_native=off pcie_pnp_en` is the safe path; native mode
    is unimplemented on 7.3)
  - 0212/0216: cacheinfo / resctrl-mpam not ported (inert in our config)
