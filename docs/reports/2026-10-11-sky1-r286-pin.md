# Sky1 default kernel pin: r285 -> r286 (7.3.0-rc6-sky1-ncz)

Under the unified 7.3 policy (`docs/reports/2026-10-05-kernel-channel-policy.md`)
the Sky1 arm64 default, installer and rescue entries all boot one kernel. This
change moves that pin from r285 to r286. The KVER string does not change
(`7.3.0-rc6-sky1-ncz`); the build revision, image, modules, headers and the
committed accelerator overlays do not change content-wise either, because r286
only adds static functions (see below) — so the SAME overlay `.ko` mirror stays
valid and the DKMS/ABI surface is unchanged.

## What r286 is

- Source lineage is unchanged: `v7.3-rc6` (`a90ee4305c4a`) +
  `sky1-ncz-v7.3-rc6-port.patch` (sha256 `9be6f5f3...c6594`) + recipe patches
  `0001`-`0011` (r284/r285 review + dmesg-noise fixes).

  (sha256 `d5668a3c...f4ce`), from `ncz-os/linux-cix`

## Why the overlays did NOT have to be replaced

r285 -> r286 changes only `trilin_dptx.c` and adds only `static` functions: no
exported symbol and no symbol CRC changes, so the kernel's `Module.symvers` is
CRC-identical for every symbol the out-of-tree accelerators reference.

`build/verify-overlay-modversions.py` (which checks every committed overlay
`.ko`'s `__versions` table against the pinned kernel's `Module.symvers`):

- r286: 0 CRC mismatches, 0 unresolved symbols in all six modules
  (`mali_kbase`, `memory_group_manager`, `protected_memory_allocator`, `aipu`,
  `panthor`, `amvx`).

Contrast r282 -> r284, where the overlays had to be re-mirrored (648 CRC
mismatches). Here they must not change; re-mirroring would be a no-op at best
and a provenance lie at worst. `overlays_mirrored` in `sky1-manifest.json`
therefore keeps the same six sha256 values.

## Rescue entry

Rescue boots this same kernel with `RESCUE_ARM64_BLACKLIST`
(`assets/kernel/KERNEL-POLICY`), matched by
`assets/refind/ncz-refind-refresh.sh`; unchanged by this pin.

## The packaged debs

`make kernel-debs` (reached via `make vendor-mirror` -> `offline-mirror` during
the image build) rebuilds the three Sky1 packages from the pinned
`assets/kernel/mainline`: `linux-image-cixmini`, `linux-headers-cixmini` and
`cixmini-boot` at `BUILD_REV=r286` (derived from the staging directory name).
The rebuild is byte-reproducible (`build/build-kernel-debs.sh`; pin-anchored
`SOURCE_DATE_EPOCH=1791201600` from `manifests/base.pin`) — verified with two
consecutive builds on ULTRA. The reviewed ledger rows in
`manifests/ncz-packages.tsv` carry those reproducible sha256 values; the
provenance-inputs gate compares the published `build/kernel-debs/*.deb` bytes to
them.

## Risk

- The DP-AUX recovery is validated by the operator's supervised `.66` boot
  (0 aux errors, greeter bound 227 ms with the fixed module loaded) but the
  in-tree change is unverified by the KVM/DKMS gates for the Sky1-only DP
  behaviour (they cannot model it). Acceptance for this pin rests on the
  operator's "I'm calling your fix a fix".
- Same-KVER-ness means a board that upgrades in place keeps the same `uname -r`;
  only the Debian package revision (`+r286`) and the module content change. That
  is by design (the accelerator DKMS modules need not rebuild) and is the same
  property the r285 pin relied on.
