# amd64 7.3.0-rc6-4-t2-edge-aer9010: plain AER revert, CGROUP_DMEM off, nouveau fix

The amd64 unified 7.3 kernel for the 26.10 respin is
**`7.3.0-rc6-4-t2-edge-aer9010`** (`assets/kernel/amd64-stable/KVER`). It
replaces `7.3.0-rc6-3-t2-edge-aer9011`, which the policy verifier now refuses.
Default, installer and rescue entries all boot it (`assets/kernel/KERNEL-POLICY`).

## What changed against rc6-3

| Change | Why |
|---|---|
| AER: 9010, the plain revert of `eddba19b8b5f` ("PCI/AER: Support Advisory Non-Fatal Errors", v7.3-rc1), replaces the narrow 9011 quirk (ANFE masked on the Apple T2 Secure Enclave 106b:1802 only) | Operator decision 2026-10-06. Alex Deucher reported on LKML that the commit breaks non-Apple boards too and that reverting it fixes them, so the revert is the right fix for every machine. The operator also asked for everything else added 2026-10-04..06 to mitigate the T2 power cut to be removed (below). Drop 9010 once upstream fixes or reverts `eddba19b8b5f`. |
| `CONFIG_CGROUP_DMEM` off | With it on, `nvidia-kernel-open-dkms` 615.71.09 does not build (`os-interface.c:3031`, `dmem_cgroup_register_region()` takes a `const struct dmem_cgroup_init *` since 7.3). |
| 9012, upstream `4d0e27041185` (nouveau: check `gsp->rm` before the GCX-ready query) | nouveau's runtime suspend oopsed on Turing/Ampere without GSP-RM firmware (PEGASUS, RTX 2060 Mobile) and every later PCI config read of the dGPU hung. |

The flavour names the AER change it carries, so `aer9011` became `aer9010`.

## Verification

- Static gate: 21 patches (9010, 9012, 9001 applied; 9011 and 9507 not), patch
  hashes match the repo, no `CGROUP_DMEM` in the config, the headers'
  `auto.conf`/`autoconf.h`, `Module.symvers` or `System.map`, no 9011 or
  `anfe` symbol, headers and image from the same build (Module.symvers CRCs
  equal the vmlinux `__crc_*`, 12016/12016), all 4220 modules Kbuild-compressed
  with an xz CRC32 check (none hand-compressed), t2smc and t2gmux DKMS build
  with `W=1` and no warnings.
- initramfs: `dpkg -i` plus initramfs-tools; 839 initrd modules, all from this
  KVER and byte-identical to the image deb.
- KVM (OVMF, q35): boots twice (default and `pm.dpm_watchdog_enabled=1`),
  efivarfs readable, T2 in-tree stack and t2smc/t2gmux load, a module with a
  corrupted symbol CRC is refused; full dmesg captured, no oops, BUG or WARNING.
- NVIDIA: `nvidia-kernel-open-dkms` 615.71.09-2 in `debian:forky` against these
  headers builds nvidia, nvidia-modeset, nvidia-drm, nvidia-uvm and
  nvidia-peermem unpatched and with `ncz-0001` (vermagic matches).

Not verified: no hardware boot yet. qemu has no T2, no NVIDIA GPU and does not
exercise the AER path, so the T2 power cut (MEDUSA) and the nouveau runtime
suspend (PEGASUS) still need a supervised boot.
