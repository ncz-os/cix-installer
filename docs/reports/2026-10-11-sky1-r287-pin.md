# Sky1 default kernel pin: r286 -> r287 (7.3.0-rc6-sky1-ncz)

Under the unified 7.3 policy (`docs/reports/2026-10-05-kernel-channel-policy.md`)
the Sky1 arm64 default, installer and rescue entries all boot one kernel. This
change moves that pin from r286 to r287. The KVER string does not change
(`7.3.0-rc6-sky1-ncz`), so an in-place OTA keeps `uname -r`; only the Debian
package revision (`+r287`) and the kernel/module content move.

## What r287 is

- Source lineage is unchanged: `v7.3-rc6` (`a90ee4305c4a`) +
  `sky1-ncz-v7.3-rc6-port.patch` (sha256 `9be6f5f3...c6594`) + recipe patches
  `0001`-`0011` + `sky1-ncz-dptx-aux-wedge-recovery` (0012, r286).
- **Config root fix:** `CONFIG_RT_GROUP_SCHED` is no longer set. With the cgroup
  v2 `cpu` controller enabled on every boot, a `RT_GROUP_SCHED=y` kernel gives
  every non-root cgroup zero RT runtime and cgroup v2 exposes no per-cgroup
  `rt_runtime` knob, so `sched_setscheduler(SCHED_FIFO/SCHED_RR)` from any
  service cgroup returns `EPERM` even for `CAP_SYS_NICE`. rtkit therefore cannot
  grant PipeWire's `data-loop` `SCHED_RR` (it silently stays `SCHED_OTHER`) and
  the HDMI/DP sink XRUNs. This is the kernel-level root fix for the O6N audio
  cutouts (`mem_1788916884668_a8c0d2`); the userspace `DisableControllers=cpu`
  drop-in is retained as belt-and-braces. `CONFIG_CGROUP_SCHED`,
  `CONFIG_FAIR_GROUP_SCHED`, `CONFIG_CFS_BANDWIDTH` (`cpu.weight`/`cpu.max`) and
  `CONFIG_SCHED_AUTOGROUP` are unchanged.
- **CIX q3 vendor sync:** recipe patches `0013`-`0021` port the still-missing
  `cixtech/cix_opensource__linux` `cix_k6.6.89_2026q2..2026q3` fixes (see the
  `r287_patches` map in `assets/kernel/sky1-manifest.json` for the exact
  upstream commit ids of each).
- meta-cix `linux-cix-sky1-ncz_7.3-rc6.bb` **PR r6**, branch
  `fix/sky1-r287-20261011` (ARGONAS meta-cix @ `f6a82e9`, parent `a8726df` =
  r286). The r6 recipe bumps `PR = "r5" -> "r6"`, adds the nine patches to
  `SRC_URI`, bumps `R285_EXPECTED_PATCHES = "13" -> R287_EXPECTED_PATCHES = "22"`
  with per-patch presence assertions, and adds the `CONFIG_RT_GROUP_SCHED`
  build-time config guard.
- Staging: `/mnt/argonas-yocto-shared/kernel-staging/r287-7.3.0-rc6-sky1-ncz-20261011`
  (ARGONAS-side spelling `/mnt/datapool/yocto-shared/kernel-staging/...`).

## Why the overlays WERE re-mirrored this time (contrast r285 -> r286)

`CONFIG_RT_GROUP_SCHED` changes the layout of `struct task_struct` /
`struct sched_rt_entity`, which moves the exported-symbol CRCs: the r287
`Module.symvers` differs from r286 in 535 CRC values. The committed accelerator
overlays are `CONFIG_MODVERSIONS`-locked, so the r286-built `.ko` would refuse
to load on r287. All six overlays were therefore **rebuilt against the r287
build** (`build/build-accel-overlays.sh`) and re-mirrored under
`assets/kernel/{mali,npu,panthor,vpu}/7.3.0-rc6-sky1-ncz/`.
`build/verify-overlay-modversions.py` confirms **0 CRC mismatches** against the
r287 `Module.symvers`. (This is the r282 -> r284 situation, not the r285 -> r286
one, where the change was static-only and the overlays were left untouched.)

  `assets/kernel/{mali,npu,panthor,vpu}/7.3.0-rc6-sky1-ncz/` are **replaced**
  (see above).
- Test fixtures follow the pin (`build/test-kernel-default-policy.sh`,
  `build/test-arm64-freshness-gate.sh` — the pool fixture adds r287 as the newest

  The components registry is regenerated for `build_rev=r287`.
- `assets/kernel/KERNEL-POLICY`: no `MAINLINE_FRESHNESS_ACK` is needed — r287 is
  the pool's newest unified 7.3 build and the shipping pin. The gate stays
  fail-closed for any future even-newer build.
- Docs: kernel-channel policy, release notes, ARM64 build notes and inventory
  now say r287.
- The amvx DKMS source (`assets/kernel/vpu/src`) gains a bounded
  `amvx.wait_pending_retry` (default off-equivalent) knob and the vendor
  `dqbuf` `vb->memory` fix; the rebuilt `amvx.ko` overlay carries both.

## The packaged debs

`make kernel-debs` rebuilds the three Sky1 packages from `assets/kernel/mainline`
at `BUILD_REV=r287` (derived from the staging directory name). The rebuild is
byte-reproducible (`build/build-kernel-debs.sh`; pin-anchored
`SOURCE_DATE_EPOCH=1791201600`) — verified with two consecutive builds on ULTRA.
The `manifests/ncz-packages.tsv` rows carry those reproducible sha256 values.

## Risk

- The `CONFIG_RT_GROUP_SCHED` fix is validated at the scheduling-syscall level
  (the mechanism) and verified against the built `.config`; whether it fully
  eliminates the O6N cutouts is the operator's supervised boot test
  (`NEED-OPERATOR.md` in the cixsync mission dir).
- The CIX q3 ports are compile-verified (the kernel builds and both boot/ABI
  gates pass) but not metal-tested for the display/USB behaviours they touch.
- Same-KVER means in-place upgrades keep `uname -r`; only the `+r287` revision
  and the module content change. The overlays are re-mirrored, so the accelerator
  DKMS/ABI surface changes on this revision (r282 -> r284 class).
