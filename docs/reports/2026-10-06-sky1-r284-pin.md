# Sky1 default kernel pin: r282 -> r284 (7.3.0-rc6-sky1-ncz)

Under the unified 7.3 policy (`docs/reports/2026-10-05-kernel-channel-policy.md`)
the Sky1 arm64 default, installer and rescue entries all boot one kernel. This
change moves that pin from r282 to r284. The KVER string does not change
(`7.3.0-rc6-sky1-ncz`); the build revision, image, modules, headers and the
committed accelerator overlays do.

## What r284 is

- r282 source: `v7.3-rc6` (`a90ee4305c4a`) + `sky1-ncz-v7.3-rc6-port.patch`
  (sha256 `9be6f5f3...c6594`).
- r283 config changes on top: module BTF (`DEBUG_INFO_BTF`/`BTF_MODULES`),
  `DMABUF_DEBUG` off, `DRM_PANIC_SCREEN=kmsg`, `SQUASHFS_ZSTD`, and
  `MT7921U`/`MT7925U`/`RTW89_8922DE` as modules. The r284 config is
  byte-identical to r283 (sha256 `1d1be747...ac805`).

  1. trilin-dp panel lookup without `fwnode_drm_find_panel`;
  2. and 4. native PCIe mode restored, including the `sky1-pcie-cix` driver
     rename. Native mode stays **off by default** (`sky1_pcie_native=off`);
  3. the CIX early-boot runtime-PM gate (`cix_pm: system ready`).

## Why the overlays had to be replaced

The KVER string is the same, so a vermagic check cannot tell the old modules
from the new ones. The kernel is built with `CONFIG_MODVERSIONS=y`, so the
symbol CRCs decide. Checking every module's `__versions` table against r284's
`Module.symvers`:

- r284 overlays: 0 CRC mismatches, 0 unresolved symbols in all six modules.
- the r282-era overlays: 648 CRC mismatches (mali_kbase 190, panthor 223,
  amvx 131, aipu 71, memory_group_manager 19, protected_memory_allocator 14).
  On r284 they would be refused at load, and the board would boot with no
  GPU, VPU or NPU acceleration.
- control: the same r282-era overlays against r282's `Module.symvers`: 0
  mismatches.

`build/kernel-manifest.py check` and `build/verify-overlays.py` check vermagic
only, so they pass in both cases. Follow-up (stage B2): `build/verify-overlay-modversions.py`
now checks every committed overlay `.ko` against the pinned kernel's `Module.symvers`
(wired into `build/verify-arm64-inputs.sh`, fixture test `build/test-overlay-modversions.sh`);
it fails on the r282-era overlays (648 mismatches) and passes on r284's.

## Rescue entry

Rescue boots this same kernel with
`module_blacklist=panthor,panfrost,mali_kbase,memory_group_manager,protected_memory_allocator,amvx,aipu,armchina_npu,cix_vpu,linlon_vpu`
(`RESCUE_ARM64_BLACKLIST`, matched by `assets/refind/ncz-refind-refresh.sh`).
On r284 this list covers every accelerator module that exists: the overlays
`mali_kbase`, `memory_group_manager`, `protected_memory_allocator`, `panthor`,
`aipu`, `amvx`, and the in-tree `amvx.ko` (`CONFIG_VIDEO_LINLON=m`). The names
`panfrost`, `armchina_npu`, `cix_vpu` and `linlon_vpu` match no r284 module;
they are kept as harmless aliases. The display controller module is
`linlon-dp.ko` (`linlon_dp`) and is not blacklisted, so rescue keeps a display.

## Risk

- r279's four patches have not been run on Sky1 hardware on 7.3. Patch 0003
  changes boot-time runtime PM for every device. The KVM gate cannot model the
  GPU, VPU, NPU, display or PCIe, so the operator-supervised O6N boot remains
  the acceptance step before the image ships.
