# Sky1 7.3.0-rc6 edge kernel staging (r282)

Operator policy of 2026-10-05: stable 7.2.9 is the default and installer boot kernel on
both arches; Sky1 (arm64) additionally carries a bootable, non-default 7.3.0-rc6 edge
entry. This records the rc6 build that fills the arm64 edge channel and the change that
stages it into the installer assets. amd64 is out of scope here.

## Installer assets change

- `assets/kernel/edge` repointed from `r279-7.3.0-rc5-sky1-ncz-20260929` to
  `r282-7.3.0-rc6-sky1-ncz-20261004`.
- Added the rc6 accelerator overlays:
  `assets/kernel/mali/7.3.0-rc6-sky1-ncz/{mali_kbase,memory_group_manager,protected_memory_allocator}.ko`,
  `assets/kernel/npu/7.3.0-rc6-sky1-ncz/aipu.ko`,
  `assets/kernel/panthor/7.3.0-rc6-sky1-ncz/panthor.ko`,
  `assets/kernel/vpu/7.3.0-rc6-sky1-ncz/amvx.ko`.
  Their sha256 match the staging directory's `SHA256SUMS` byte for byte.
- Added `assets/kernel/edge-manifest.json`.

No consumer script changed: `build/build-squashfs-layers.sh` stages the edge payload from
`assets/kernel/edge` into the base layer and writes the `KVER_EDGE` sidecar,
`post-install/10-our-kernel.sh` installs that kernel and builds its initrd, and
`assets/refind/ncz-refind-refresh.sh` emits the non-default edge entries once the mali
overlay for the KVER is present. The default boot entry and the `default_selection`
are unchanged, so 7.2.9 remains the Sky1 default.
