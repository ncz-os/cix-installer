Arm64 Linux for CIX Sky1 boards, with the GPU, NPU and VPU actually working.

The largest release since [v12](2026.08.18-v12.md): a critical install-time
filesystem-permission fix, an installer wedge that had been silently killing
every unattended metal install since the component selector shipped, real NPU
and desktop-portal fixes, and the build-pipeline hardening that closes out a
recurring class of stale-content bug.

## Critical: root filesystem permission regression, fixed at the mechanism

A prior build shipped `/` at mode `0700` instead of `0755` on some installs.
Symptom on affected hardware: greetd panics (`unable to set working
directory: Permission denied`), the NIC never links, `rtc-efi` hangs — three
unrelated-looking symptoms from one root cause.

Root cause, proven on real hardware: `unsquashfs -f -d /target` re-stamps
`/target`'s own mode from **each** squashfs layer's root entry, and the last
layer applied wins. One layer (`desktop-hotfix.squashfs`) had root entry
`0700` — the exact ownership/permission signature `mktemp -d` produces — and
because it's the last layer extracted, it silently overwrote an
already-correct `0755` on `/`. Two earlier fix attempts missed it: one gated
a code path that turns out to be dead (`d-i partman/late_command` does not
actually run as a d-i hook), the other chased a false lead from a `chmod`
touching ctime, not mtime.

Fixed with three independent layers so this class cannot ship again:

- **Build-time gate** — `assert_squashfs_root_mode()`: every squashfs layer
  staged onto the ISO must have root entry `drwxr-xr-x`, or the build fails
  by name, before an image is ever produced.
- **Install-time gate** — the r159 debootstrap stub chmods `/target` to
  `0755` and hard-verifies it after the full layer stack (base + role +
  hotfix) extracts, rather than trusting any one layer.
- **First-boot belt** — a corrective `chmod` after `dpkg --configure -a`
  (the last unaudited code before a login screen), plus an unconditional
  `NCZ-ROOTMODE: <mode>` marker written to kmsg/console so any regression is
  visible on the very next boot's serial log, not discovered by an angry
  greetd three symptoms later.
- `build/kvm-install-gate.sh` now asserts that marker from the boot serial
  capture as part of every gated build — closing the blind spot where the
  gate reported PASS on a system whose `/` was silently wrong (`getty` runs
  as root; it can't see this class of bug).

Full mechanism writeup: [`docs/ISO-BUILD-GUARDRAILS.md`](../ISO-BUILD-GUARDRAILS.md).

## Fixed: unattended metal installs could wedge on the component prompt

Every unattended metal install since the component selector landed
(2026-08-20) could hit `Internal error! Cannot find "ok" in menu.` and stop on
a blank blue screen. Two earlier fix attempts chased missing cdebconf udebs
and template data — both healthy on the wedged box; neither was the cause.

Root cause: the component prompt ran in a backgrounded subshell. Under POSIX,
a backgrounded command's stdin becomes `/dev/null` when job control is off —
but in the d-i postinst context, stdin **is** the cdebconf reply pipe. The
subshell still wrote to the inherited fd3 (the real confmodule command pipe),
so every `SET`/`FSET`/`SETTITLE`/`INPUT` queued a reply nobody could read.
cdebconf's channel is one strictly synchronous stream shared by the whole d-i
process tree — once desynced, `main-menu`'s next read got a stale `"0 ok"`,
took the literal `ok` as a menu selection, and died.

Fixed by running the prompt synchronously in the foreground, matching every
other prompt in this installer (disk/fs chooser, username). Verified in QEMU
on the real metal cmdline (`auto=true priority=critical`, no
`ncz_components=`) with zero `Internal error` lines through a full install to
`partman`. The KVM install gate never caught this because it always injects
`ncz_components=` on the cmdline, skipping the prompt branch entirely — a real
gap in what that gate can see, worth knowing if you run your own CI against
this installer.

## NPU: real O6N fix for a silent case-mismatch install failure

The NPU install kept failing even after an earlier Python 3.11 build-time fix
had verified correct. Root cause: `cix-noe-umd` now ships its wheel as
`noe_engine-3.0.0-*.whl` (lowercase) on a case-sensitive filesystem, while the
install hook globbed for `NOE_Engine-*.whl`. The glob match failure, under
this script's `set -euo pipefail`, silently killed the *entire* hook —
including the unrelated `libnoe` install two lines below, whose wheel was
present and would have worked fine.

Both wheel lookups now use case-insensitive `find -iname` with a proper WARN
on genuine absence instead of a silent abort. Re-validated end-to-end on real
O6N against the latest `cix-noe-umd` (3.1.4, libnoe 3.1.3): `import libnoe`,
`import NOE_Engine`, and `Engine.list_adapters()` all confirm the NPU
adapter. `build/validate-accelerators.sh` (new this release — checks GPU,
NPU and VPU are each not just loaded but actually *bound and functional*) now
passes NPU where it previously failed.

## Desktop fixes

- **Sensor panel: two-column layout and neutral clock color restored.** A
  build shipped an out-of-date `ncz-singularity-desktop` payload missing its
  two-column layout for long detail lists, with the clock/temperature
  readout rendered in the accent color instead of neutral (visible as
  unexpected red text depending on theme). Root cause and the build-pipeline
  fix that closes it are below, under "Build-pipeline hardening." Verified
  directly from the shipped `.deb` inside this ISO, not from the version
  string: two-column layout, neutral `text_color` clock rendering, and the
  monitor-resolution screenshot fix are all present in
  `pool/main/ncz-singularity-desktop_20260827+bk3~gcorrectedtwocolumn1_arm64.deb`.
- **Screenshots now actually work.** Root cause: this board has no dedicated
  `xdg-desktop-portal-singularity` binary of its own, so the installer fell
  into a WARN-only branch and never wired a portal backend for
  Screenshot/ScreenCast at all. A wlr-backend fallback config shipped in the
  payload but was never staged, and even its filename was wrong for this
  session's `XDG_CURRENT_DESKTOP` value. Fixed: the correct fallback config
  is staged under the name xdg-desktop-portal actually searches for.
- **GNOME Online Accounts now actually runs.** Only the build headers
  (`libgoa-1.0-dev`) were ever installed — `goa-daemon` never shipped, so
  Online Accounts silently did nothing. Fixed, and folded in a related gap:
  `xdg-desktop-portal-singularity`'s systemd preset was never applied for
  the real user, so the portal that correctly *received* Screenshot requests
  was never actually running to answer them.
- **HDMI audio autoswitch** added for Sky1 boards, and a related asset-path
  bug that silently dropped it entirely from one build is fixed.
- **Chromium's silent-audio bug is now fixed in source, not live-patched.**
  Chromium's out-of-process audio-service isolation was breaking the
  renderer-to-audio-service shared-memory handoff on this board — Chromium
  built a structurally healthy-looking PipeWire stream (correct volume,
  correct link, correct format) that delivered all-zero PCM samples. The fix
  previously existed only as a live edit on one test board; it now ships in
  the image.
- **App selection: GTK-only.** Dropped `kdenlive` (KDE) and `vlc` (Qt) —
  `celluloid` (native GTK4) and `mpv` already cover media playback.
  `kdenlive` was also what pulled in `kwallet6`, which `xdg-desktop-portal`'s
  wildcard fallback then exposed as the system-wide Secret backend; that's
  excluded now too, independent of the app-selection change.
- `vainfo` (VA-API diagnostics) added alongside the existing `mesa-utils` /
  `vulkan-tools` GPU diagnostic set.
- `zenity` and the `singularity.portal` declaration are now staged correctly.

## Installer reliability

- A time-sync hook now runs before any HTTPS-dependent install step.
- DKMS rebuilds are now gated on actual header upgrades rather than
  running unconditionally, and a kernel r256 postinst DKMS force-rebuild bug
  is fixed.
- Disk detection and DKMS verification hardened; `hw-detect` udeb for disk
  detection is now a hard requirement instead of an implicit assumption.
- Diagnostics telnet console hardened: usable pty, direct shell launch via
  busybox login, SSH udeb install deferred so it doesn't race `anna`, and
  repeated log spam from the deferral collapsed to log-once.
- Progress now shows during the previously-silent early_command window.

## Build-pipeline hardening

This release closes out a recurring class of bug: a rebuild that looked
unchanged (same version string, or a build that "succeeded") silently shipped
stale or wrong content. Concretely:

- **Reproducible squashfs builds.** `mksquashfs` was producing a different
  output hash for byte-identical staged input — its superblock's own
  creation-timestamp field isn't covered by `-all-time`, and default
  multi-threaded packing can reorder blocks non-deterministically. Both are
  now pinned (`-all-time 0 -fstime 0 -processors 1`), verified by building
  the same input twice and comparing sha256 (byte-identical).
- **The sensor-panel regression's actual root cause**: two independent local
  source lineages of the same panel-fix work existed on the build host, and
  a version-stamping gap in `build-singularity-deb.sh` let a rebuild from
  the wrong lineage produce the *same* package version string as a prior,
  correct build — so the staleness check saw "already published" and never
  republished the fix. The vendor-mirror source-directory selection that let
  this happen is fixed at the root.
- `build/validate-accelerators.sh` added: checks GPU, NPU and VPU are each
  bound and functional, not merely that a kernel module loaded.
- The dominant staleness chain in `sinty-out-sync` is fixed at the root
  rather than patched at each symptom.
- `desktop-hotfix.squashfs` is now a real ISO build dependency (it was
  possible to ship without a committed builder for it at all), and
  superseded `ncz-singularity-desktop` `.deb`s are pruned automatically
  instead of accumulating.
- `build/test-under-di-busybox.sh` added — tests scripts under the real d-i
  BusyBox rather than a host stand-in, which had already let one quoting bug
  (`awk`) and one missing-applet bug (`stat`) ship in prior root-mode gate
  rounds before being caught here.
- `kvm-install-gate.sh` is now wired into the release flow as
  `make iso-verified`.

- **USB, network** — peripherals and primary NIC enumerate normally.
