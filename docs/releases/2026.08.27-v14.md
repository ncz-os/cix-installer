Arm64 Linux for CIX Sky1 boards, with the GPU, NPU and VPU actually working.

The largest release since [v12](2026.08.18-v12.md): a critical filesystem
permission fix, an installer wedge fix, NPU/desktop-portal fixes, and
build-pipeline hardening.

## Critical fix: root filesystem permissions

`/` could ship at mode `0700` instead of `0755` on some installs, breaking
greetd, networking, and RTC. Fixed with a build-time gate (refuses to
package a squashfs layer with the wrong root mode), an install-time
re-verify after all layers extract, and a first-boot corrective pass with a
boot-log marker for fast detection if it ever regresses. Full technical
writeup: [`docs/ISO-BUILD-GUARDRAILS.md`](../ISO-BUILD-GUARDRAILS.md).

## Fixed: unattended metal installs could wedge on the component prompt

Every unattended metal install since the component selector shipped
(2026-08-20) could hang on `Internal error! Cannot find "ok" in menu.` — a
cdebconf synchronization bug in how the prompt was launched. Fixed by running
it synchronously in the foreground, matching every other installer prompt.
Verified clean through a full unattended install in QEMU.

## NPU: install failure fixed

A case-sensitive filename mismatch (`cix-noe-umd`'s wheel is now lowercase)
was silently aborting the entire NPU install hook, including an unrelated
package below it that would have worked fine. Fixed with a case-insensitive
lookup. Verified end-to-end on real O6N: NPU adapter loads and enumerates.
`build/validate-accelerators.sh` (new) checks GPU, NPU, and VPU are each
bound and functional, not just loaded.

## Desktop fixes

- **Sensor panel**: two-column layout for long detail lists and neutral
  clock/temperature color restored (a build had shipped stale panel content).
  Verified directly against the shipped `.deb`
  (`ncz-singularity-desktop_20260827+bk3~gcorrectedtwocolumn1`).
- **Screenshots work again** — the portal backend that answers
  Screenshot/ScreenCast requests is now correctly staged and named.
- **GNOME Online Accounts now runs** — the daemon was missing, not just its
  headers; the portal service that handles it is now enabled for real users.
- **HDMI audio autoswitch** added for Sky1 boards.
- **Chromium's silent-audio bug is fixed in source** (was a live-only patch
  on one test board before).
- **App selection is GTK-only now**: dropped `kdenlive` and `vlc` (Qt/KDE);
  `celluloid` + `mpv` cover media playback. Also removes `kwallet6` from the
  system Secret backend.
- `vainfo` (VA-API diagnostics) added alongside `mesa-utils`/`vulkan-tools`.
- `zenity` and the Singularity portal declaration now stage correctly.

## Installer reliability

- Time-sync now runs before any HTTPS-dependent install step.
- DKMS rebuilds are gated on actual header upgrades; a kernel r256 postinst
  DKMS force-rebuild bug is fixed.
- Disk detection and DKMS verification hardened.
- Diagnostics telnet console hardened (usable pty, direct shell launch,
  no more SSH-udeb install race).
- Install progress now shows during the previously-silent early_command
  window.

## Build-pipeline hardening

- **Reproducible squashfs builds** — identical input now always produces an
  identical output hash (`mksquashfs` pinned to deterministic mode).
- **Fixed the root cause of the sensor-panel regression above**: the
  build-pipeline source-directory selection and version-stamping that let a
  stale rebuild collide with an already-published version string.
- `build/validate-accelerators.sh` added (GPU/NPU/VPU bound + functional
  check).
- `desktop-hotfix.squashfs` is now a real, enforced ISO build dependency;
  superseded `ncz-singularity-desktop` `.deb`s are pruned automatically.
- `build/test-under-di-busybox.sh` added — tests installer scripts under the
  real d-i BusyBox instead of a host stand-in.
- `kvm-install-gate.sh` wired into the release flow as `make iso-verified`.

## Hardware validation

### Radxa Orion O6N (default GPU config — vendor `mali_kbase`)

Verified on real hardware, this build:

- **GPU** — Mali-G720-Immortalis enumerates via both Vulkan and OpenCL 3.0.
- **NPU** — full 3-core probe (`zhouyi-v3`), `/dev/aipu` present.
- **VPU / VA-API** — H264 decode + encode entrypoints present.
- **Audio** — confirmed working, `cixsky1` ALSA card with 3x I2S devices.
- **Sensor panel** — confirmed working.
- **USB, network** — peripherals and primary NIC enumerate normally.

### Minisforum MS-R1

Verified on real hardware, this build:

- **NPU** — `/dev/aipu` present, driver loaded.
- **VPU** — `amvx` and video pipeline modules load.
- **Sensor panel** — confirmed working.
- **USB, network** — peripherals and primary NIC enumerate normally.

Tested with the alternate `panthor`/Mesa GPU path (`sky1.gpu=mesa`) rather
than the default vendor driver. On that path, Vulkan device enumeration,
OpenCL, and VA-API do not currently work — panthor/Mesa GPU compute and
media acceleration on this board are not yet at parity with the vendor
driver O6N ships by default. Tracked for a future release.

## Known issues

- **HDMI audio autoswitch can drop the active sink on boards with more than
  one real audio device** (e.g. MS-R1, which has both an onboard HDA codec
  and the Sky1 I2S HDMI path — O6N has only one, so this did not surface in
  O6N-only testing). The autoswitch daemon and PipeWire's own default-sink
  policy can end up briefly fighting for control, which can interrupt
  playback. Fix planned for the next release: move CIX-specific HDMI/DP
  detection into PipeWire's own device-priority policy instead of polling
  and force-setting the default sink.
