# NCZ-OS 26.7 "Maximilian" — installer 2026.08.18-v13

Arm64 Linux for CIX Sky1 boards, with the GPU, NPU and VPU actually working.

| | |
|---|---|
| ISO | `nclawzero-installer-cixmini-2026.08.18-v13.iso` |
| md5 | `582c7061036bc5200877129800fdf224` |
| size | 3.4 GB |
| kernel | `7.2.0-sky1-ncz` |
| base | Debian forky (testing), arm64 |
| desktop | Singularity (labwc / wlroots, native Mali GLES) |

A maintenance release on top of [v12](2026.08.18-v12.md). Same kernel, same
drivers, same desktop. Everything below is about recovery access and the
documentation of it.

## Recovery credentials are now configurable

The two break-glass surfaces — the `ncz-failsafe` console on `:2323` and the
`ncz-recovery` container — take their passwords from configuration rather than
carrying one fixed value.

| Surface | Default | Override at bake time |
|---|---|---|
| `ncz-failsafe` (telnet `:2323`) | `failsafe` | `NCZ_FAILSAFE_PASS=<pass>` |
| `ncz-recovery` container (SSH, own IP) | `recovery` | `NCZ_MGMT_PASS=<pass>` |

Setting either to `random` generates a unique per-install passphrase instead —
20 characters in four groups, short enough to type over a serial console. The
generated value is written to `/etc/ncz/failsafe-password` (mode 0600) and
printed in the install log.

These defaults are published on purpose, the same choice already made for the
installer diagnostics account (`diags`) and the rescue partition (`rescue`): on
a home LAN with no public route, a recoverable machine beats an unrecoverable
one. **Change them on any network you do not control.**
[`docs/REMOTE-ACCESS.md`](../REMOTE-ACCESS.md) covers the full default-access
posture and how to turn each piece off.

## Failsafe console now stores a hash

The failsafe console prefers a sha512 hash over storing the passphrase in
clear. That path depended on a `cryptpw` applet the bundled static busybox does
not include, so it never actually ran. It now tries busybox, then `openssl`,
then `python3`, and reports which produced the hash. Plaintext remains only as
a genuine last resort, in a root-only 0600 file.

## Build-time credential gate

`make iso` now runs `build/secret-scan-gate.sh` against the finished image and
fails the build if a credential is found in it. The gate also learned a shape
it previously could not see — a literal default inside a shell parameter
expansion, `SOME_PASS="${SOME_VAR:-...}"` — while allowing the documented
product defaults above through, so it stays quiet enough to be worth reading.

## Documentation

- **The `ncz` utility** is documented for the first time: every subcommand, and
  the fact that nothing under `ncz install` or `ncz agent` is installed or
  running by default.
- **`ncz install mnemos`** — how the memory server is deployed (rootless podman
  quadlet, persistent SQLite, `:5002`, installed offline from a bundled image
  with `Pull=never`).
- **NPU embeddings** — the values that matter: `nomic-embed-text-v1.5_256.cix`,
  768 dimensions, mean pooling, served on `:8081` in the OpenAI shape. Models
  are not on the ISO; they come from apt or `ncz models pull`. A dimension
  mismatch does not error, it silently poisons retrieval.
- **The live recovery container** now has a section explaining *why* it exists,
  not just how to reach it. The rescue partition is cold: it needs a reboot and
  a working bootloader, so it cannot help a running system. The container is
  live — its own LAN address, the host root bind-mounted read-write at `/host`,
  and container root equal to host root so that mount is genuinely writable. It
  carries its own userspace, so it survives a host whose `/usr/lib` is gone and
  where `sshd` will not run.

## Corrections

**USB Type-C Power Delivery works, and previous notes said it did not.**
Measured on O6N: the `rts5453` driver binds and `/sys/class/typec/port0`
reports `usb_power_delivery_revision 3.0`, `usb_typec_revision 1.2`,
`power_role [source]`, `vconn_source yes`. The
`module_blacklist=typec_rts5453,rts5453` token on the boot cmdline is **inert**
— the driver is built in, and `module_blacklist` only affects loadable modules.
It is a leftover from an earlier kernel that does not reproduce on 7.2.
Alt-mode (DisplayPort-over-Type-C) is still not wired up.

**Mainline status was overstated.** Earlier documentation said Sky1 support
"does not exist in mainline Linux". CIX is actively upstreaming the platform
and core SoC enablement is landing; what is still missing upstream is the rest
of what a desktop needs — display, GPU, NPU, VPU and much of the SoC glue —
which is what the vendor patch series carries.

## Upgrading

No reinstall is required for the credential changes; they apply to new
installs. On an existing system you can set the failsafe passphrase directly:

```bash
printf %s '<your passphrase>' | sudo tee /opt/ncz-failsafe/etc/recovery.secret >/dev/null
sudo chmod 0600 /opt/ncz-failsafe/etc/recovery.secret
sudo systemctl restart ncz-failsafe.service
```

and the container account with `sudo machinectl shell ncz-recovery /bin/sh -c 'passwd root'`.
