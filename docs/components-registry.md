# NCZ-OS component registry

Operator directive **2026-10-05** (Item C1, phase 1). This is the canonical
component inventory for `cix-installer`. It supersedes the ad-hoc per-hook
apt-get / dpkg / npm list, the manual `docs/platform-inventory.tsv` cross
references for *what* a hook installs, and the implicit-but-undocumented
"every package in `manifests/*.pkgs` is mandatory" posture.

The registry has three parts:

- **`manifests/components.tsv`** — the registry itself (TSV; one row per
  component per install path). Generated by `build/gen-components-registry.py`
  from the ground-truth files; curated rows for kernel / DKMS / npm /
  hook-only / vendor staged-deb / firmware / overlay live in the generator
  and are emitted deterministically. 642 rows as of 2026-10-06.
- **`build/components.py`** — the checker / reporter. Pure Python 3 stdlib;
  runs on STUDIO (macOS) and the Linux build hosts. `check`,
  `report --arch A --variant V`, `diff-published`. Network-free in phase 1;
  `check` exits non-zero on drift; `diff-published` degrades gracefully when
  the published-apt report isn't local.
- **`build/test-components.sh`** — fail-before / pass-after fixture test for
  `check`, driven by a hermetic mini repo
  (`build/fixtures/components-fixtures/mini-repo/`) that carries its own
  manifests, hooks, mirror script, allowlist, dkms assets and published
  report. The real registry is never touched. bash 3.2 compatible.

Phase 1 shipped the registry, the checker and the drift report. Phase 2
enforces `required`, `version_floor` and `arch` (`components.py check --gate`,
wired into `make parity` and `build/lint-platform.sh`). Phase 3 generates the
seed files, the `NCZ_LOCAL_DEBS` block and confirms the parity allowlist from
the registry (`build/gen-components-registry.py --render-*`). The phase plan
at the bottom of this file records what each phase does.

## Format

`manifests/components.tsv` is a TSV. Lines starting with `#` are comments;
blank lines are ignored. The first non-comment line is the header. The
column order is fixed and matches `build/components.py:HEADER`; do not
reorder.

| # | column          | meaning                                                          |
|---|-----------------|------------------------------------------------------------------|
| 1 | `name`          | short package name; for npm / staged-deb / firmware / overlay /  |
|   |                 | dkms / kernel rows the curated identifier (e.g. `t2smc`,         |
|   |                 | `sky1-mainline-kernel`, `@anthropic-ai/claude-code`).            |
| 2 | `kind`          | one of `debian`, `ncz-apt`, `staged-deb`, `npm`, `dkms`,         |
|   |                 | `kernel`, `overlay`, `firmware`                                  |
| 3 | `source`        | `debian-forky`, `buildkite-packages`, `r2`, `staged:<path>`,     |
|   |                 | `npm:<pkg>`, `vendored:<path>`                                   |
| 4 | `arch`          | `all` \| `arm64` \| `amd64`                                      |
| 5 | `variant`       | one or more of `desktop`, `server`, `rescue`, `mgmt`, `installer`|
|   |                 | (comma-separated), or `all`                                      |
| 6 | `required`      | `yes` \| `no` \| `conditional:<cond>` — is the component         |
|   |                 | required for the image to function. (Raw NCZ_LOCAL_DEBS          |
|   |                 | `required`/`optional` values are normalized to yes/no and        |
|   |                 | preserved in `notes`.)                                           |
| 7 | `version_floor` | minimum acceptable version, e.g. `7.2.9-sky1-ncz` for the        |
|   |                 | arm64 mainline kernel. Mandatory for `kernel` and `dkms` rows.   |
| 8 | `installed_by`  | hook or build script that installs the component, OR             |
|   |                 | `manifest` (for rows whose install is implicit in the apt        |
|   |                 | resolver). May include a parenthesized annotation.               |
| 9 | `verified_by`   | verify*.sh / check*.sh that audits the install; may be a         |
|   |                 | comma-list; may include a parenthesized annotation. Must be      |
|   |                 | non-empty and the file(s) must exist.                            |
| 10 | `provenance`   | source-of-truth: manifest path, dkms.conf, keyring, PROVENANCE   |
|   |                 | file, etc. Must be non-empty.                                    |
| 11 | `notes`        | free-form, single line, tabs escaped as spaces.                 |

### Kind semantics

| kind          | source values                            | typical install path                                  |
|--------------|----------------------------------------|---------------------------------------------------|
| `debian`     | `debian-forky`                        | `apt-get install` from `manifests/*.pkgs` or a   |
|              |                                       | hook (e.g. `systemd-coredump`, `wpasupplicant`)   |
| `ncz-apt`    | `buildkite-packages`, `r2`           | `apt-get install` against the NCZ apt repo       |
| `staged-deb` | `staged:<path>`                       | `dpkg -i <path>` or `apt-get install` from a    |
|              |                                       | pre-staged offline pool .deb (NCZ_LOCAL_DEBS,    |
|              |                                       | vendor-mirror pool)                              |
| `npm`        | `npm:<pkg>`                          | `npm install -g <pkg>`                            |
| `dkms`       | `vendored:assets/kernel/<name>`      | `dkms build/install` against the staged source    |
| `kernel`     | `vendored:<path>` (Sky1=assets/kernel| `dpkg -i <deb>` or symlink -> NFS staging         |
|              |  /mainline, /edge; AMD64=            |                                                   |
|              |  assets/kernel/amd64-stable)        |                                                   |
| `overlay`    | `vendored:<path>`                    | symlink + DKMS rebuild against the active kernel |
| `firmware`   | `staged:<path>` (assets/firmware/...) | `cp -a` or extract to `/lib/firmware/...`         |

### Plain-debian rows

Every package named in any `manifests/*.pkgs` gets at least one row. The
generator unions cross-variant occurrences into one row per
`(name, kind, source, arch)` so the same package, present in
`desktop.pkgs`, `installer-base.pkgs`, `rescue.pkgs`, and `mgmt.pkgs`
(different variant columns) becomes a single row whose `variant` is the
union `desktop,installer,rescue,server,mgmt` (the `server` slot is reserved
for the future server variant; right now server ships the same closure as
desktop minus the desktop-only seed rows).

`install-extra.pkgs` seeds that are plain Debian packages installed by a
post-install hook (`sudo`, `installation-report`, `popularity-contest`) are
emitted as `kind=debian source=debian-forky` rows, not ncz-apt.

### Why one row per `(name, kind, source, arch)` and not per package

A package can have multiple install paths. `ncz-singularity-desktop` is
both an apt package (Buildkite / R2 per item AC) AND a locally-staged .deb
fallback (two NCZ_LOCAL_DEBS rows in `build-desktop-mirror.sh`). The
registry carries one row per install path so the `check` tool can audit
each one independently. Removing a row without removing the install path
is the drift `check` catches.

Names matching the NCZ-apt namespace rule (`ncz-*`, `cix-*`, `*-ncz-*`)
seeded in a manifest get an `ncz-apt source=buildkite-packages` row; if the
name is not in the generator's `AC_PUBLISHED` set the row's notes say it is
pre-AC / unpublished and `diff-published` + the drift report track it.
`KNOWN_UNPUBLISHED_SEEDS` (currently `ncz-screensavers-plugin`) skip the
apt row entirely: their staged-deb pool row is authoritative (item AC open
question 5 — published set does not contain the plugin).

## How to add a component

1. **Plain-debian row from a manifest**: add the package name to the
   appropriate `manifests/*.pkgs`, then regenerate:
   `python3 build/gen-components-registry.py`. The new row appears under
   the right `(arch, kind=debian, source=debian-forky)`.
2. **NCZ-OS apt package**: add the name to a manifest (e.g.
   `install-extra.pkgs`), ensure it is published to Buildkite / R2, and
   add it to `AC_PUBLISHED` in the generator (with the publication cited).
   If it is NOT published, add it to `KNOWN_UNPUBLISHED_SEEDS` and give it
   a `staged-deb` pool row instead.
3. **Vendor staged .deb (vivaldi / chrome / cix-noe-umd / cixmini
   kernel-build debs / ncz-usb-recovery)**: add a curated row to
   `VENDOR_DEB_ROWS` in the generator, or add a `NCZ_LOCAL_DEBS` entry to
   `build/build-desktop-mirror.sh` (the generator parses it).
4. **Hook-only install** (a hook `apt-get install`s a package no manifest
   seeds): add a curated row to `HOOK_ONLY_ROWS` in the generator
   (`kind=debian source=debian-forky`, or `staged-deb` when it comes from
   the vendor-mirror pool, e.g. `cix-noe-umd`).
5. **DKMS module**: add `assets/kernel/<name>/dkms.conf` (+ `PROVENANCE`);
   the generator's `parse_t2_dkms_modules()` picks it up.
6. **Kernel entry**: edit `assets/kernel/KERNEL-POLICY` and
   (if necessary) `parse_kernel_entries()`. Keep the AMD64 edge stamp in
   the repo (the directory `assets/kernel/amd64-edge/` does not yet exist;
   when the 7.3.0-rc6-1-t2-edge-aerfix deb is on disk, drop a `KVER` file
   there).
7. **Overlay (.ko)**: edit `assets/kernel/edge-manifest.json` (or
   `assets/kernel/mainline/<driver>/<kver>/...`); `parse_overlay_rows()`
   picks up the `overlays_mirrored.<drv>/<kver>/<ko>` entries
   automatically.
8. **NPM global**: add a curated row to `NPM_ROWS`.
9. **Firmware blob**: add a curated row to `FIRMWARE_ROWS` (the asset is
   gitignored; the registry row is what the `check` tool sees).

## Re-generating

```sh
python3 build/gen-components-registry.py           # writes manifests/components.tsv
python3 build/components.py check                   # audits the registry
bash build/test-components.sh                       # hermetic fixture test
```

The generator is deterministic (rows sorted by name, then kind, arch,
variant) so a re-run produces a byte-identical file if the ground-truth
files are unchanged. The TSV may be hand-edited, but the generator will
overwrite hand-edits on the next re-run; do not edit the TSV by hand for
rows the generator already covers. The curated lists in the generator
(kernel / DKMS / npm / hook-only / vendor / firmware / overlay) are the
only rows worth editing by hand, and only if the generator's heuristic is
wrong.

## Operating the checker

```sh
python3 build/components.py check                        # exit 1 on drift
python3 build/components.py check --gate                 # phase 2 enforcement entry
python3 build/gen-components-registry.py --render-seeds --render-local-debs --render-allowlist --check
python3 build/components.py check --report-out PATH      # also write the drift report
python3 build/components.py report --arch amd64 --variant desktop
python3 build/components.py diff-published
```

Global flags: `--root DIR` (repo root; default: parent of `build/`) and
`--registry PATH` (registry TSV; default `<root>/manifests/components.tsv`).
They exist so the hermetic fixture test can point the checker at
`build/fixtures/components-fixtures/mini-repo` without touching the real
tree.

`check` findings (errors => exit 1):

| code                | fires when                                                    |
|---------------------|---------------------------------------------------------------|
| `row-format`        | kind / source / arch / variant / required outside the approved vocabulary (`required`: yes \| no \| `conditional:<cond>`) |
| `row-installer`     | `installed_by` names a file that does not exist               |
| `row-verifier`      | `verified_by` is empty or names a file that does not exist    |
| `row-provenance`    | `provenance` is empty                                         |
| `kind-shape`        | `kernel`/`dkms` without `version_floor`; `staged-deb`/`npm` with the wrong source prefix |
| `manifest-registry` | a `manifests/*.pkgs` package has no registry row              |
| `mirror-registry`   | an NCZ_LOCAL_DEBS entry has no registry row                   |
| `hook-registry`     | a hook apt-get/dpkg/npm install has no registry row (backslash-continuation aware) |
| `required-optional` | a `staged-deb` row's `required` contradicts the NCZ_LOCAL_DEBS flag; a `required=yes` manifest row no manifest seeds |
| `seed-published`    | an NCZ-namespace name seeded in a manifest is absent from the published NCZ apt set (item AC report) |
| `arch-allowlist`    | `build/arch-parity-allowlist.tsv` side disagrees with the registry arch set |
| `hook-arch`         | a hook runs on arch A and installs a package whose registry rows are for the other arch |
| `hook-never-runs`   | a `required=yes` row's installer hook appears in no `hooks.list.*` |

Warnings (do not affect the exit code):

| code                | fires when                                                    |
|---------------------|---------------------------------------------------------------|
| `dkms-provenance`   | a dkms `vendored:assets/kernel/<name>` source dir has no `PROVENANCE` file |

Notes on two subtle scopes:

- **`required-optional` only compares `staged-deb` rows** against the
  NCZ_LOCAL_DEBS flag: the flag describes optionality of *staging the .deb
  into the desktop mirror*, not component necessity. Example:
  `ncz-singularity-desktop`'s arm64 ncz-apt row is `required=yes`
  (20-desktop.sh hard-fails without it) while its pool rows are optional to
  stage — that is not drift.
- **`seed-published` reads the published set offline** from the item AC
  report (`~/Projects/oc-apt-publish/report.md`, override
  `NCZ_APT_PUBLISH_REPORT`). When the file is absent the check prints a
  `DEGRADED:` note and skips this category.

`check` does NOT write a report by default; pass `--report-out` to write
one. The drift report is a **report**, not a fix; the items it surfaces feed
S4 and phase 2. `--no-exit` prints findings without exiting non-zero
(incident triage).

`report --arch A --variant V` prints the contents of an image of that
arch/variant, grouped by kind and source, with required/floor shown.
Useful for sanity-checking a release image. Exits 0.

`diff-published` compares `kind=ncz-apt source=buildkite-packages` (or
`r2`) registry rows against `~/Projects/oc-apt-publish/report.md`. The
report file is read locally — no network is touched. If the report file is
missing, it exits 0 with a `DEGRADED:` note. Always informational (exit 0);
a `NOT-IN-DOCSET` finding means "not in the AC table", not necessarily
"not in the apt repo".

## Provenance per row

Every row carries a `provenance` column pointing at the file that is the
ground truth for that row:

- plain-debian rows: the `manifests/<name>.pkgs` file (or the hook, for
  hook-only rows)
- ncz-apt rows: the manifest that seeds the name + the NCZ apt repo
  (publication state is audited by `diff-published` against the item AC
  report, not tracked per row)
- staged-deb rows: the `build/build-desktop-mirror.sh` NCZ_LOCAL_DEBS row
  or the vendor-mirror pool that staged the .deb
- DKMS rows: `assets/kernel/<name>/dkms.conf` (a missing `PROVENANCE` file
  is a `check` warning, not encoded in the row)
- kernel rows: `assets/kernel/{amd64-stable/KVER, edge-manifest.json,
  mainline -> NFS staging}` and `assets/kernel/KERNEL-POLICY`
- overlay rows: `assets/kernel/edge-manifest.json` (the
  `overlays_mirrored.<drv>/<kver>/<ko>` field)
- firmware rows: the staged path in `assets/<firmware>/...` (the asset is
  gitignored; the row describes it)

## Open questions / phase-2 hand-offs

1. **ncz-screensavers-plugin unpublished** — confirmed by item AC open
   question 5; seeded in `install-extra.pkgs` but absent from the published
   set. `check` flags it (`seed-published`). Phase 2 / S4: publish it or
   guarantee the pool entry.
2. **Pre-AC publications undocumented** — `ncz-ffmpeg` and
   `chromium-ncz-sky1` resolve from the live NCZ apt repo today but are not
   in the AC table. Extend the published-artifacts documentation so the
   offline published-set source is complete.
3. **T2 DKMS PROVENANCE files** — only `assets/kernel/t2smc/PROVENANCE`
   exists; `t2gmux`, `t2smp`, `t2thunderbolt` lack one. `check` warns
   `dkms-provenance`. Phase 2 should land real PROVENANCE files.
4. **Wallpaper .debs (`ncz-wallpapers-*`)** — staged under
   `assets/wallpaper-debs/`, not yet in the registry; the package set grows
   as packs ship (`build/build-wallpaper-contrib-deb.sh`). Phase 2 needs a
   curated row per `ncz-wallpapers-*` (or a wildcard entry).
5. **CIX closed-source userspace debs** — `post-install/25-cix-proprietary.sh`
   `dpkg -i`s a quoted array (`${DEBS[@]}`) the hook scanner intentionally
   does not resolve, so only `cix-noe-umd` (the one documented as
   "not published" in `build/build-gst-cix.sh`) has a row. `cix-vaapi`,
   `cix-libva*`, `cix-vpu-firmware`, … need curated `staged-deb` rows.
6. **ncz-usb-recovery cross-mirror inconsistency** — `optional` in the
   desktop-mirror pool but the vendor-mirror build treats it as required
   (`build/build-vendor-mirror.sh` errors when cixmini-boot is built and no
   ncz-usb-recovery deb exists). Phase 2: make the pool entry `required`
   or the cixmini build tolerant.
7. **Intel OpenVINO source gap** — `post-install/54-gpu-accel.sh` installs
   the OpenVINO stack from `apt.repos.intel.com/openvino`; the approved
   `source` vocabulary has no third-party-apt value, so those rows use
   `debian-forky` as an approximate label. Add an approved source value in
   phase 2.
8. **Arch-parity-allowlist semantics** — the allowlist is about *manifest*
   parity (a package in one of `<m>.pkgs` / `<m>-amd64.pkgs` but not the
   other). `ncz-singularity-desktop` is `arm64-only` there (not seeded in
   `desktop-amd64.pkgs`) while the registry carries arm64 ncz-apt +
   arch-all staged-deb rows; the `arch-allowlist` check compares the
   allowlist side against the registry arch set and passes. Keep the two
   vocabularies aligned in phase 2.

## Phase plan

Per the operator directive, three phases land across three merge windows:

- **Phase 1 (this item)** — read-only inventory + drift report. `check`
  is NOT wired into CI or any build. `check` exits non-zero on real
  drift; the drift report `docs/reports/2026-10-06-components-drift.md`
  documents every inconsistency without fixing them. Phase 1 ships:
  - `manifests/components.tsv`
  - `build/gen-components-registry.py`
  - `build/components.py`
  - `build/test-components.sh` + `build/fixtures/components-fixtures/mini-repo/`
  - `docs/components-registry.md` (this file)
  - `docs/reports/2026-10-06-components-drift.md`
- **Phase 2** — enforce `required: yes`, `version_floor`, and
  `arch` from the registry. Lands after items S1 (merge r2) and S4
  (mandatory screensaver install). Will fail closed if a
  `required: yes` row is missing from a published mirror, if an installed
  version is below `version_floor`, or if a row's `arch` doesn't match
  the running arch. Lives behind a feature flag
  (`NCZ_REGISTRY_ENFORCE=1`) so S1 / S4 failures can be diagnosed without
  the registry failing them first.
- **Phase 3 (this item)** — generate `manifests/*.pkgs`, the
  `NCZ_LOCAL_DEBS` block and confirm `build/arch-parity-allowlist.tsv`
  from the registry. The hand-written files stay the byte-identity
  target: comment headers, inline-comment padding and the order of the
  data lines are preserved, so a regen of an unchanged tree rewrites
  nothing. A hand-edit that the registry does not cite fails
  `--check`. The edit path is: edit `manifests/components.tsv` (or the
  curated lists in `build/gen-components-registry.py`), run
  `python3 build/gen-components-registry.py` to refresh the registry,
  then `python3 build/gen-components-registry.py --render-seeds
  --render-local-debs --render-allowlist` and commit both. Do not edit
  a `*.pkgs` package line or an `NCZ_LOCAL_DEBS` data line by hand; the
  generator will reject it.
  `build/test-components-generate.sh` is the hermetic fail-before /
  pass-after proof. `make parity` and `build/lint-platform.sh` run the
  `--check` form, so a drifted seed fails the build.
