# Chromium upstream patch

## 0001-media-gpu-enable-av1-hw-decode-for-v4l2-on-linux.patch

One line in `media/gpu/args.gni`. On Linux, `use_av1_hw_decoder` is gated on
VA-API, so a build with `use_v4l2_codec=true` / `use_vaapi=false` compiles out
AV1 hardware decode entirely — silently. The V4L2 code is otherwise ready:
`v4l2_utils.cc` already defines `V4L2_PIX_FMT_AV1` as `v4l2_fourcc('A','V','0','1')`
and `v4l2_device.cc` already accepts it during format enumeration.

Evidence gathered on CIX Sky1 (Radxa Orion O6):

- The VPU advertises AV1: `v4l2-ctl -d /dev/video0 --list-formats-out` →
  `[7]: 'AV01' (AV1 OBU Stream, compressed, dyn-resolution)`.
- It decodes AV1 **correctly**: an ffmpeg build carrying a V4L2 AV1 m2m decoder
  produced output bit-identical to dav1d — same MD5 across the first five
  frames of a 720p clip. So the silicon and kernel driver are fine; only the
  Chromium buildflag is in the way.

### Who this helps — and who it does not

It helps anyone **building** Chromium for V4L2 hardware: distributions and ARM
SoC vendors. Today they enable `use_v4l2_codec`, get H.264/VP9/HEVC, and lose
AV1 with no diagnostic.

It does **not** reach Google Chrome. Chrome's desktop Linux build ships
`use_v4l2_codec=false` and `use_vaapi=true`, so the code this unlocks is not in
Chrome at all — confirmed on this board, where Chrome 151 produced zero V4L2 log
lines and never opened a video node even with every relevant feature flag set.
Chrome would additionally require Google to enable `use_v4l2_codec` for desktop
Linux, which is a much larger ask and arguably wrong for the mainstream Linux
population (Intel/AMD/NVIDIA are VA-API; V4L2 stateful is an ARM-SoC concern).

**For Chrome, the route to AV1 on Sky1 is the CIX VA-API driver**, not this
patch. Chrome already has hardware AV1 compiled in and actively selects
`VaapiVideoDecoder` for AV1 — see `docs/HW-VIDEO-DECODE-STATUS.md`; it fails
only because `cix_vaapi` returns nothing.

### Submitting

Chromium uses **Gerrit, not GitHub pull requests**:

1. Sign the Google CLA (individual): <https://cla.developers.google.com/>
2. `git clone https://chromium.googlesource.com/chromium/tools/depot_tools.git`
   and put it on `PATH`.
3. In a Chromium checkout: `git checkout -b av1-v4l2-linux origin/main`,
   apply this patch, `git commit`, then `git cl upload`.
4. `Change-Id` is generated by the commit hook — the placeholder in the patch
   must be replaced (or dropped so the hook fills it in).
5. Suggested reviewers: OWNERS of `media/gpu/` — the V4L2 and media/gpu
   directories list active reviewers.

Expect a maintainer to ask whether the gate was deliberate, since desktop-Linux
V4L2 AV1 has not been widely exercised. The Sky1 measurements above are the
counter-evidence: the hardware path works and is verified bit-exact; only the
flag withholds it.
